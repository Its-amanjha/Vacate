# Decisions

Every non-obvious choice and every deviation from [docs/SPEC.md](docs/SPEC.md). Newest last.
Owner: Claude. Partners propose entries in their hand-off.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-11-19 | Own directory walker on `DirectoryInfo.EnumerateFileSystemInfos()` instead of `EnumerationOptions`. | `EnumerationOptions` (`IgnoreInaccessible`, `AttributesToSkip`) does not exist in .NET Framework, so it breaks PowerShell 5.1. The walker skips reparse points and catches access errors per directory, giving the same behaviour on both. |
| D2 | 2026-11-19 | Per-rule timeout is a cooperative deadline checked inside the walker on every entry. | 5.1 has no `-Parallel`; runspaces add complexity and non-determinism. A deadline check stops a rule within one entry of the limit. |
| D3 | 2026-11-19 | Registry key last-write time is reported as `null` with reason "not available without native API". | .NET `RegistryKey` does not expose it; getting it needs P/Invoke via `Add-Type`, which the spec bans (no compiled helpers, no dynamic code). |
| D4 | 2026-11-19 | JSON Schema validation tests run only on PowerShell 7. | `Test-Json` does not exist in 5.1. The 5.1 job runs the loader's own structural checks. |
| D5 | 2026-11-19 | macOS is deferred until a Mac is available. macOS rules ship `verified: false`. | Project owner has no Mac yet. Will be `ci-verified` once GitHub Actions runs, and verified later on a real Mac. |
| D6 | 2026-11-19 | Linux verification uses WSL Ubuntu 24.04. | Available locally. WSL differs from a desktop install (no GUI apps by default, `/mnt/*` Windows drives, no real block devices). Rules seen only via fixtures stay `verified: false`. |
| D7 | 2026-11-19 | One rule per JSON file, named `<rule-id>.json`. | Lets several agents add rules in parallel without merge conflicts; the loader checks the file name equals the id. |
| D8 | 2026-11-19 | Rules live per platform folder; `platforms` must include the folder's platform. The spec's example rule (three platforms + `LOCALAPPDATA`) would be rejected by the spec's own token rule, so cross-platform rules are split per platform. | Keeps the token rule enforceable. |
| D9 | 2026-11-19 | Path locator gains optional `recurse` (sum sizes/counts below each match), `include` (file-name glob when recursing) and `excludeHome` (skip the current user's profile, for "other users" rules). | The spec needs folder sizes, a capped `.DS_Store` count and other-profile names, which a one-segment glob alone cannot express. |
| D10 | 2026-11-19 | One trace per matched target (per glob match), not one per rule. | The spec requires a concrete `resolved` locator per trace. |
| D11 | 2026-11-19 | Report gains top-level `skipped[]` (`ruleId`, `reason`, `detail`) and categories are a fixed enum of 18. | The spec's report section 7 needs skip reasons, but the sample JSON had nowhere to put them. |
| D12 | 2026-11-19 | `Glob`, reparse and cloud-placeholder checks live in `Private/Primitives.ps1`. | PathJail and Providers both need them; one copy avoids drift between parallel authors. |
| D13 | 2026-11-19 | Unix root detection uses `[Environment]::UserName -eq 'root'`. | .NET resolves it from the effective uid; no external `id` binary and no P/Invoke needed. |
| D14 | 2026-11-19 | Rule paths are checked twice: syntax at load time (`RuleLoader`), and again by the path jail at scan time. | Defence in depth: a bad rule is rejected before any scan, and the jail still refuses anything that slips through. |
| D15 | 2026-11-19 | An invalid rule file never loads; the rest of the catalog still loads and the errors are listed. `rules validate` exits 1 on any error. | One bad file must not hide the other 70 rules; `rules validate` is the gate in CI. |
| D16 | 2026-11-19 | Rule loader is `Import-VacateRuleSet` (singular noun). | PSScriptAnalyzer `PSUseSingularNouns`; the spec requires a clean lint. |
| D17 | 2026-11-19 | Checklist and report name vendor guidance by article title ("Recovery options in Windows", "Erase your Mac"), never by URL. | URLs go stale and cannot be checked offline; an exact title is searchable and cannot point somewhere wrong. Keeps the HTML free of any link-out. |
| D18 | 2026-11-19 | Report carries `catalog.rules[]` (id, category, title, whyItMatters, sensitivity, source, verified). | The HTML details section must show "why it matters" and the rule source, and `report -Run <dir>` must re-render from the JSON alone. |
| D19 | 2026-11-19 | Each checklist step lists categories; a step appears when it is always-on (backup, account sign-out, encryption status, erase guidance) or has matching traces. Every category maps to at least one step per platform (tested). | "Derive from traces" while never dropping the steps that matter even when nothing was found (Find My, Microsoft account, erase guidance). |
| D21 | 2026-11-19 | Rule ids are unique **per platform**, not globally: `browser.chrome.history` may exist once in `windows/` and once in `linux/`. A duplicate is the same id applying to the same platform twice. | Same artifact, same name on every OS keeps reports and checklists readable; traces carry `platform` so nothing is ambiguous. `rules show <id>` shows every platform's version. |
| D22 | 2026-11-19 | (Pi) `Invoke-VacateSystemQuery -Platform` accepts a platform name or a profile object; the "binary missing → unavailable" gate applies to the default runner only, an injected `-Runner` owns execution. | Lets the ok/timeout/error paths be tested on Windows, where `/usr/bin/*` does not exist. Production always uses the default runner. |
| D23 | 2026-11-19 | (Pi) Profiles normalise roots with string helpers, not `[IO.Path]`. Environment snapshot keeps only non-empty values. | `Path.GetDirectoryName` ignores `\` on Linux, which broke the Windows profile under the Ubuntu test job. Absent and blank env vars mean the same thing. |
| D24 | 2026-11-19 | (Pi) Pester `-Skip`/`-ForEach` values are computed at file scope, not in `BeforeAll`. | Pester 5 evaluates them at discovery, before `BeforeAll` runs. |
| D25 | 2026-11-19 | `-Redact` hashes names and path segments with HMAC-SHA256 under a random per-run key (`h-` + 10 hex). Drive letters, registry hives, WMI class locators, rule ids, counts, sizes and times are kept. Free text is scrubbed paths-first, then known names. | Same name gives the same hash inside one report (so structure stays readable), but hashes cannot be reversed by dictionary or matched across two reports. Path-first scrubbing was a real leak caught by a test (`C:` replaced before the path detector ran). |
| D26 | 2026-11-19 | All JSON reading goes through `ConvertFrom-VacateJson`, which turns PowerShell 7's auto-parsed `[datetime]` values back into ISO strings. | PowerShell 7 `ConvertFrom-Json` converts date strings to `[datetime]` (5.1 does not), which changed report text on a round trip; caught by a redaction test. |
| D27 | 2026-11-19 | Rule status is recomputable from report.json: failed = distinct ruleIds in errors; skipped = distinct ruleIds in skipped with no trace and no error; run = total - failed - skipped. complete = no budget/timeout skip. A rule with traces plus a partial permission skip counts as run. | Spec rule 3: no summary number that cannot be recomputed from the JSON. |
| D28 | 2026-11-19 | The tool may live inside a scanned root (most people unzip into Downloads). Its own folder and `runs/` are passed to every scan as excluded paths, and `Output.ps1` is the only writer and refuses any path outside `runs/`. | The spec says output must sit outside scanned roots; refusing to run from Downloads would make the tool unusable. Excluding the tool and output folders keeps the intent: vacate never scans or reports its own files. |
| D29 | 2026-11-19 | Paired sorts use the non-generic `[Array]::Sort([Array]keys, [Array]items, [Collections.IComparer]...)`. | PowerShell binds the generic overload by copying the items array, so the original stayed unsorted. Caught by an engine test; was latent in RuleLoader and PathJail. |
| D20 | 2026-11-19 | Wallets go in the first "back up" step (write down recovery phrases). | The spec's checklist has no wallet step; losing a seed phrase is irreversible, so it must come before anything else. |
