# vacate — Phase 1 specification (source of truth)

> Copied verbatim from the project owner's brief on 2026-11-19. Do not edit this file to make
> work easier. Deviations go in `DECISIONS.md` with a reason.

## Mission

Build `vacate`: a cross-platform handover tool that finds the personal data and traces a person leaves on a computer before they sell, return, recycle, or give it away, and produces a report a normal person can act on. It runs on **Windows, macOS and Linux** from one shared engine.

Phase 1 is an **audit**. It scans, explains, and generates a de-link checklist. It does not delete, move, clean, or "fix" anything, ever. Destructive actions come later, behind separate gates.

The product's only real value is that it does not lie. A scanner that invents paths, miscounts, or says "clean" when it isn't is worse than no tool. Prefer fewer, verified traces over more, plausible ones.

## Why this exists

Every OS's "reset" flow is not a data-erasure standard, and people routinely hand over machines still holding browser sessions, saved passwords, Wi-Fi keys, cloud tokens, SSH keys and wallet files. Existing options are either guidance-only checklists or blind cleaners, and almost none cover all three desktop platforms. The gap is a tool that is **complete about what it finds, explicit about what it cannot see, and safe by construction**.

## Non-negotiables

1. **Phase 1 writes nothing.** No deletion, no moves, no registry or plist writes, no launch agents, no systemd units, no network. The only write target is the run output folder (`runs/<timestamp>/`), which must sit outside every scanned root.
2. **Metadata only.** Never open, read, parse, decrypt, or upload file contents. Size, timestamps, counts, names. No SQLite queries, no browser DB reads, no Keychain/GNUPG decryption, no plist/YAML parsing.
3. **Evidence over claims.** Every trace has a rule id, a concrete locator, and a source. No trace without a locator. No summary number that cannot be recomputed from the JSON.
4. **Path jail.** Every scoped location resolves under allow-listed roots for the current platform. Refuse `..`, absolute overrides, junctions, symlinks, cloud placeholders that would hydrate, other volumes, and other users' contents. Other profiles may be reported by **name only**. Resolve links before comparing, and compare with the platform's case rules.
5. **Rules are data.** Detection rules live in `rules/<platform>/*.json`, validated at load. Adding an artifact must not require editing code. Each rule declares `platforms` and may only use root tokens defined for those platforms.
6. **Honest limits.** The report has a mandatory, platform-specific "What this does not see" section. Do not soften it.
7. **Local only.** No telemetry, no accounts, no network calls, no update check.
8. **No shell, no unlisted commands.** Everything in-process. The only external reads allowed are named `system-query` locators mapped in code to fixed absolute binaries with fixed arguments: `fdesetup status` (macOS), `lsblk --json` and `findmnt --json` (Linux). No shell interpolation, no user input, 5s timeout, failure recorded as skipped. On Windows, use read-only CIM cmdlets and no binaries. Never `sudo`, never a credential prompt.
9. **Least privilege, and no root by default.** Unelevated/unprivileged by default. On macOS and Linux, refuse to run as root unless `-AllowRoot` is passed, because root can read other users' data and that breaks the privacy model. Record admin-only rules as skipped with a reason. `-Elevated` only asserts that the session is already elevated; the tool never elevates itself.
10. **Deterministic.** Stable rule order, trace order, and JSON key order. The same machine scanned twice produces identical output apart from timestamps and durations.

## Phase 1 scope

### In scope

- `vacate.ps1` CLI, works on Windows, macOS and Linux:
  - `scan` — auto-detect the platform, run the matching rule pack, write `runs/<timestamp>/`
  - `rules list` / `rules show <id>` / `rules validate`
  - `report -Run <dir>` — re-render HTML/Markdown from JSON
  - `checklist -Run <dir>` — regenerate the de-link checklist
  - `version`
- Rule catalog: **60+ rules, 20+ per platform**, in three packs
- Shared read-only scan engine with per-rule timeouts, a global budget, and per-rule error capture
- Outputs per run: `report.json`, `report.html`, `summary.md`, `checklist.md`, `scan.log`
- Self-contained HTML (no CDN, no external fonts, no JS required to read)
- JSON Schemas checked into the repo
- Pester tests and PSScriptAnalyzer clean
- Docs: `README.md`, `LIMITS.md`, `THREAT-MODEL.md`, `RULES.md` (generated from the catalog), `DECISIONS.md`

### Out of scope — do not build

- Any deletion, reset, cleanup, uninstall, or settings write
- Secure erase, NVMe sanitize, ATA secure erase, FileVault key destruction, LUKS header destruction, BitLocker key purge, free-space overwrite
- GUI, tray app, installer, code signing, auto-update
- Claude/agent skill wrapper
- Scheduling, background scanning, telemetry, accounts
- Reading file contents or decrypting anything
- Mobile OSes (iOS, Android)

If Phase 1 seems to need any of these, stop and report instead of expanding scope.

## Data model

Rule:

```json
{
  "id": "browser.chrome.history",
  "platforms": ["windows", "macos", "linux"],
  "category": "browsers",
  "title": "Chrome history database",
  "whyItMatters": "Shows every site visited and when.",
  "sensitivity": "high",
  "locator": {
    "kind": "path",
    "root": "LOCALAPPDATA",
    "path": "Google/Chrome/User Data/*/History",
    "match": "files"
  },
  "measure": ["exists", "sizeBytes", "lastWriteTime", "itemCount"],
  "maxEntries": 5000,
  "requiresElevation": false,
  "verifiedOn": ["Windows 11 24H2", "macOS 15", "Ubuntu 24.04"],
  "verified": true,
  "source": "Chromium user-data docs; path confirmed per platform",
  "notes": null
}
```

Locator kinds — keep this list small:

- `path` — glob under a root token. `*` matches one segment only. Files or directories.
- `registry` — key existence, value count, subkey count, last-write time. Windows only.
- `wmi` — a read-only CIM query with named properties. Windows only.
- `installed-program` — specialization of the uninstall registry keys, both views. Windows only.
- `system-query` — a named, allow-listed query (`filevault-status`, `block-devices`, `mounts`). No raw commands in data.

No command execution from data, no arbitrary code, no script blocks.

## Scan engine requirements

- **Platform detection.** One helper returns `windows`, `macos` or `linux`. Do not rely on `$IsWindows` in 5.1; use edition plus runtime checks.
- **Rule filtering.** Load only rules whose `platforms` include the current platform. Others count as `rulesNotApplicable`, not errors.
- **Injected context.** Roots, registry base, providers, and the platform module are passed in, so tests can point at a temp profile and a test registry key. Production uses fixed roots; there is no hidden override flag in the CLI.
- **Provider boundary.** `ReadOnlyFileSystem` and `ReadOnlyRegistry` expose read operations only. Tests use a write-spy that fails on any write attempt.
- **Enumeration.** Use .NET `Directory.EnumerateFiles` with `IgnoreInaccessible` and `AttributesToSkip = ReparsePoint` in hot paths. Never recurse through junctions or symlinks. Never open a file handle beyond metadata.
- **Path comparison.** Case-insensitive on Windows and macOS, case-sensitive on Linux. Normalize separators. Treat `/var` and `/private/var` as the same place on macOS. Reject paths that escape the root after resolution.
- **Caps.** `maxEntries` per rule (default 5000). When hit, stop enumerating, set `truncated: true`, and say so in the report.
- **Budgets.** Per-rule timeout defaults to 10s; global budget defaults to 120s (`-BudgetSeconds`). On exhaustion: stop starting new rules, mark the rest `skipped: budget`, finish the report. Partial results are valid and must be labelled incomplete.
- **Errors.** A rule failure never aborts the scan. Record `{ruleId, message, type}` in `errors[]` and continue.
- **Permission skips.** Unreadable paths are `skipped: permission`, never errors. On macOS this includes TCC-protected folders when Full Disk Access is not granted.
- **Elevation.** Detect once. If a rule needs elevation and it isn't available, record `skipped: requires-elevation`; do not attempt, do not fail.
- **System queries.** Only named queries from `SystemQueries.ps1`, each with an absolute binary path, fixed argument array, 5s timeout, and no shell. Record the parsed value, not raw output. A missing binary is `skipped: unavailable`.
- **Determinism.** Sort traces by category then rule id. Stable JSON property order. No per-trace data that isn't real metadata.
- **Self-exclusion.** Never scan `runs/`, the tool's own folder, or the output folder.
- **Report privacy.** Treat `report.json` like a password. `-Redact` output must be shareable. Put a warning in the HTML header and README.
- **Encoding.** UTF-8 JSON, HTML-escaped strings, handle non-ASCII and long paths.

## Report requirements

HTML, single file, prints cleanly, readable with JS off. Sections in order:

1. **Header** — platform, machine, user, time, elevated or not, tool version, sensitivity warning.
2. **Summary** — one paragraph: what was found, count, total size, whether the scan was complete.
3. **By category** — table: category, traces found, size, highest sensitivity, what it means.
4. **Details** — per trace: title, why it matters, resolved locator, size/count, last modified, rule source, verified status.
5. **De-link checklist** — ordered, generated.
6. **Installed programs** — name, publisher, install date, scope where available.
7. **Skipped and failed** — rule id, reason (elevation, budget, permission, unavailable, error).
8. **What this does not see** — the mandatory platform-specific limitations.
9. **Methodology** — read-only statement, rule count, budget, rule catalog version.

Markdown summary: same facts, no lines wider than 100 characters, suitable for pasting into a handover note.

## Checklist generation

Derive from traces, using a platform-specific template. Signing out and exporting must come before uninstalling, because uninstalling can remove the session you need to sign out.

**Windows:** back up files → export browser data, sign out of sync → sign out of Microsoft account → record BitLocker recovery key status → transfer licenses → sign out of cloud clients → uninstall session-holding apps → remove Wi-Fi/VPN/mapped drives/printers/Bluetooth → clear browser/credential files → reset or erase (out of scope; link to Microsoft guidance).

**macOS:** back up files → export browser data, sign out of sync → turn off Find My Mac and Activation Lock → record FileVault recovery key status → sign out of Apple ID/iCloud → transfer licenses → sign out of cloud clients → uninstall apps → remove Wi-Fi/VPN/printers/Bluetooth → clear browser data, Keychain items, SSH keys → Erase All Content and Settings (out of scope; link to Apple guidance).

**Linux:** back up files → export browser data, sign out of sync → transfer licenses (Steam, etc.) → sign out of cloud clients → remove SSH/GPG keys → clear shell history and recent files → disable autostart and user services → uninstall apps → remove Wi-Fi/VPN/printers/Bluetooth → reinstall or destroy the LUKS header (out of scope; link to distro guidance).

Every checklist item names the traces it came from.

## Platform limitations to write down

**All:** SSD spare area, cloud/backup copies, firmware/TPM/BIOS/EFI persistence, data already deleted but not overwritten, other OS installs, encrypted containers, swap and hibernation files, memory.

**Windows:** BitLocker recovery keys held in Entra/AD, TPM ownership, other drives, other user profiles' contents.

**macOS:** TCC-protected data without Full Disk Access, FileVault recovery keys held by Apple/iCloud, APFS local snapshots, Secure Enclave, Keychain items that require unlocking.

**Linux:** root-only files without privilege, LUKS keyslots, swap, journal contents, container images, distro-specific package state, other mounted systems.

## Testing

### Unit (no network, no real profile)

- Rule loader: rejects duplicate ids, unknown category, missing source, empty locator, bad root token, token not defined for a declared platform, `..`, absolute paths, unknown locator kind, oversized `maxEntries`.
- Path jail: per platform, rejects junctions/symlinks, other-user paths, other-volume paths, cloud placeholders; accepts valid globs; handles long paths; normalizes `/var` and `/private/var` on macOS.
- Glob engine: `*` matches one segment only; no regex injection.
- Case rules: wrong case fails on Linux; wrong case matches on Windows and macOS.
- Trace aggregation: sizes, counts, last-write selection, sample cap.
- Redaction: names hashed, counts preserved, no raw paths remain.
- Checklist ordering: dependencies respected per platform.
- System queries: only allow-listed names, absolute binaries, fixed args, no shell.

### Integration (temp fixture per platform)

- A fixture tree with known artifacts produces exactly the expected trace set.
- A clean fixture produces zero traces.
- A symlink (macOS/Linux) or junction (Windows) inside the fixture is skipped, not followed.
- An unreadable file (ACL deny on Windows, `chmod 000` on Unix) records a permission skip, not a crash.
- Budget exhaustion produces a partial report marked incomplete.
- The write-spy records zero write attempts outside `runs/`.
- A static test asserts no `Invoke-WebRequest`/`Invoke-RestMethod`/`System.Net` client usage and no unlisted external binary invocation.
- Rules for other platforms are counted as not applicable and never executed.

### Report

- JSON validates against the schema.
- HTML contains no unescaped user-controlled strings (fixture with `<script>` in a filename).
- HTML renders with JS disabled and prints (manual check recorded).
- Markdown and JSON agree on counts.
- Redacted output contains no raw usernames, file names, or volume names.

### Harness self-test

Deliberately break one component at a time and confirm the suite fails: force `exists = $true`; drop a rule; skip the junction/symlink guard; ignore the budget; disable redaction; let a wrong-platform rule run. Record the mutations in `DECISIONS.md`. A suite that stays green under sabotage is broken.

### Performance

- A full scan of a synthetic 50k-file profile completes within the 120s budget on each platform.
- A single rule never exceeds its timeout when pointed at a huge tree.

### CI matrix

- Windows: `windows-latest` with both `powershell` and `pwsh`
- macOS: `macos-latest` with `pwsh`
- Linux: `ubuntu-latest` with `pwsh`
- Every job runs unit + integration + report tests and uploads a sample report artifact.

## Agent operating rules

1. **Build order:** models → rule loader → providers/path jail → platform modules → scan engine → Windows rules → macOS rules → Linux rules → report renderer → checklist → CLI → tests. Tests alongside each, not after.
2. **Never stub a test to green.** If a criterion cannot pass, leave it failing and explain why.
3. **Never invent a path.** Verify it, or mark it unverified. The report must say which.
4. **Ambiguity → simplest defensible choice → `DECISIONS.md`.** Do not ask; do not gold-plate.
5. **No network, ever**, in code or tests.
6. **Never add deletion "while you're here."** Phase 1 is read-only. If a cleanup feature seems needed, stop and report.
7. **No platform hacks in shared code.** If the engine needs OS-specific behaviour, it goes in the platform module behind one interface.
8. **Every new dependency** needs one line of justification in `DECISIONS.md`. Aim for zero.
9. **Security posture from day one:** least privilege, no `Invoke-Expression`, no dynamic code, no writing inside scanned roots, encode all output, never run as root by default.

## Roadmap — context only, do not build

- **Phase 2 — Guided cleanup.** A plan per trace: what to remove, how, risk, and an export-first warning. Dry-run only.
- **Phase 3 — Safe deletion.** Allow-listed roots, symlink resolution, Recycle Bin/Trash default, exact-path registry/plist allowlist, `-Execute -Confirm <MACHINENAME>`, verification re-scan, undo log.
- **Phase 4 — Real erase.** NVMe sanitize, ATA secure erase, FileVault key destruction and Erase All Content and Settings, LUKS header destruction, free-space overwrite, firmware checks, verification, and a signed NIST SP 800-88-aligned certificate. Hardware qualification matrix per platform.
- **Phase 5 — Packaging and trust.** Signed binaries (Authenticode, notarized macOS, signed Linux packages), reproducible builds, agent-skill wrapper, shareable redacted reports.
- **Phase 6 — Mobile and servers.** iOS/Android handover guidance; headless server mode.

Every phase keeps Phase 1's guarantees: evidence before claims, limits written down, dangerous actions behind explicit gates.

## Legal and ethical scope

For devices the user owns or is authorized to erase. Not for destroying evidence, defeating a legal hold, or falsifying records. State this in the README and the report footer.
